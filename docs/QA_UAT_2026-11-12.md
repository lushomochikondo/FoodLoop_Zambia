## Accessibility finding

The initial live WCAG A/AA automated sample covered 32 combinations of page, role, width and theme. Twenty samples reported text contrast failures; none reported horizontal overflow. The only reported rule was `color-contrast`, affecting login branding, dashboard secondary text, dark heatmaps, notification labels and organisation details. A targeted stylesheet correction and repeat audit are part of this QA work. A passed automated audit does not establish full accessibility compliance.

Correction outcome: the repeat 32-sample audit with local CSS cleared the original findings but identified two donor-dashboard samples affected by the new secondary-text rule. A final targeted correction passed all four donor-dashboard combinations (light/dark, mobile/desktop). The full existing theme/browser regression check also passed again for donor, beneficiary and administrator fixtures. The stylesheet fix is local and has not been committed, pushed or deployed; production therefore still requires this correction to be released.

## Reusable checks

`qa/hosted_readonly_check.py` writes ignored timing/status evidence to `qa/hosted-readonly-results.json`.

`qa/hosted_accessibility_check.py` writes ignored results to `qa/hosted-accessibility-results.json`, with local-CSS/focused suffixes for subsequent scoped runs. Setting `FOODLOOP_QA_LOCAL_CSS=1` substitutes the local workspace stylesheet into production page rendering for pre-release verification; such a run is not verification that the stylesheet has been deployed. Optional `FOODLOOP_QA_ROLES` and `FOODLOOP_QA_PATHS` select comma-separated roles and paths.
